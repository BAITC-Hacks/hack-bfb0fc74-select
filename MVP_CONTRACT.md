# MVP Select — трек 06

Зафиксировано 23.09.2026 по указанию пользователя. Документ закрепляет существующий контракт `models.py`, не меняет архитектуру.

## Границы

Вход — параметры мероприятия и запроса: город, дата, формат мероприятия, категория подрядчика, бюджет в тенге; язык и длительность в часах необязательны.
Выход — от нуля до трёх подрядчиков с именем, категорией, городом, начальной ценой и конкретными причинами совпадения на основе каталога.

Город, категория, бюджет, формат, указанные язык и длительность — строгие ограничения. Занятые на выбранную дату исключаются, включая площадки. Пустой max_hours означает неприменимость ограничения. Даты вне 23.09–31.12.2026 отклоняются: доступность неизвестна.

Используются только исходные 66 профилей. Синтетические записи явно помечаются, как и заполненные в датасете город/цена. Цена показывается «от» и не гарантирует итоговую смету.

Не входят: бронирование, уведомления, векторный поиск, новые профили, новые поля пожеланий. Архитектура остаётся Python + Streamlit + CSV, один процесс; API объяснений необязателен.

## Контракт подбора и интерфейса

- `Request(city, date, event_format, category, budget_kzt, duration_hours=None, language=None)` — неизменяемый dataclass.
- `match(profiles, request) -> MatchResult` — детерминированный отбор, без сетевых вызовов.
- `MatchResult(status, cards, eligible_count, category_count, exclusion_counts)`.
- `cards: tuple[Profile, ...]` содержит максимум три профиля в окончательном порядке. Флаги `synthetic`, `city_imputed`, `price_imputed` передаются без потери.
- `status`: `matched` — есть совпадения; `no_category` — категории нет в городе; `no_eligible` — категория есть, никто не проходит условия.
- `eligible_count` — общее число подходящих до ограничения до трёх; `category_count` — число профилей категории в городе.
- `exclusion_counts`: `busy`, `budget`, `format`, `language`, `duration`. Считается первое невыполненное условие в этом порядке, поэтому один профиль учитывается один раз.
- Дата вне календаря, неположительный бюджет или длительность, отсутствие обязательной строки вызывают `ValueError`; интерфейс показывает ошибку. Непустое значение города/категории/формата без совпадений обрабатывается как пустой результат. Форма предлагает только значения из каталога.
- `build_explanations(result, request, use_ai=False) -> (dict[id, text], mode)`, где mode — `local`, `ai` или `fallback`. Объяснения не меняют состав/порядок; при ошибке API используются локальные факты.

Ранжирование: упоминание формата в описании по фиксированному словарю, затем начальная цена по возрастанию, затем ID. Это эвристика соответствия, не рейтинг качества.

## Состояния и демонстрация

При 1–2 совпадениях показать все и причину нехватки: малый каталог либо ограничения. При нуле различать отсутствие категории и отсев. При смене только даты объяснять изменение состава занятостью.

Проверка без API: `python -m pytest -q`; запуск: `python -m streamlit run app.py` после установки requirements.

Демонстрация: Алматы / ведущий / свадьба / 2 млн ₸ / 11.10.2026 → три карточки из пяти; 10.10 → другая тройка; флорист / 300 тыс. / 10.10 → одна; Астана / декоратор → категории нет; Алматы / ведущий / 100 тыс. → никто не проходит.
